# ADR-001: Structured Strict TDD evidence is authoritative

- Status: proposed
- Change: strict-tdd-evidence-remediation-fast-path
- Date: 2026-07-18

## Context

The current Markdown evidence table is readable but cannot reliably distinguish harmless marker drift from missing, unverifiable, or fabricated TDD evidence. Repairing prose heuristically could manufacture compliance.

## Decision

`apply-progress.md` will contain exactly one directly parseable `json:strict-tdd-evidence` schema-v1 block with task cycles, test references, phase statuses, provenance, and functional snapshot. The Markdown `TDD Cycle Evidence` table is a deterministic human rendering of that record. Only rendering drift from a complete valid record is an `evidence-format-gap`; a missing or invalid structured record remains CRITICAL and is never synthesized by the fast path.

## Alternatives

- Keep Markdown as authority: marker parsing cannot prove semantic equivalence or provenance.
- Repair malformed JSON heuristically: turns ambiguity into fabricated evidence.
- Remove the table: loses the existing human-readable apply/verify contract.

## Consequences

Classification and repair become deterministic and testable, while reports remain readable. Apply producers must emit both representations and verify must cross-check them. Legacy records without JSON use ordinary remediation; rollback removes both representations' new contract together.
