# ADR-004: A dedicated installer owns ~/.cursor and sync-cursor.js is deleted

- Status: proposed
- Change: cursor-native-target
- Date: 2026-07-25

## Context

`~/.cursor` is the intended install destination, but the shared `install-target.js`
`assertSafeDest` guard explicitly refuses `$HOME`. The current implementation of
`setup:cursor` / `reload:cursor` is the untracked, never-released `scripts/sync-cursor.js`,
which copies source files without `toolMap` substitution (REQ-install-005 / REQ-install-006).

## Decision

Create `scripts/configure/install-cursor.js`: resolve `path.join(os.homedir(), ".cursor")`,
run `runConfigure({ target: "cursor", validate })`, apply a local `assertCursorPathSafe`
(refuse filesystem roots, symlinked root or destination, canonical escape from the managed
root) before any write, sync `dist/cursor` by content comparison, write `hooks.json` with
`__OSPEC_CURSOR_ROOT__` already expanded, and copy the hooks binary via the shared
`copyBinaryToTree`. `--dry-run` performs no writes. `package.json` repoints
`setup:cursor` / `reload:cursor` and `scripts/sync-cursor.js` is deleted in this change.

## Alternatives

- Reuse `assertSafeDest` — wrong by construction: it rejects the destination we need.
- Keep `sync-cursor.js` as a thin delegating wrapper for one release cycle — dead code with no
  external consumer, since the script is untracked and never shipped.

## Consequences

Install becomes generator-first and idempotent, and Cursor stops drifting from the other
targets. `~/.cursor` gains a managed-path guard that Cursor's own tooling does not provide;
pre-existing files from the ad-hoc sync (e.g. `scripts/configure/**`) remain until manually
removed, because the installer never prunes. Reversible only by restoring the deleted script
from git history, which is a documented rollback step in the proposal.
