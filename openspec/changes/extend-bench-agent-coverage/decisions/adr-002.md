# ADR-002: Prefix grammar and closed-set failure semantics

- Status: proposed
- Change: extend-bench-agent-coverage
- Date: 2026-09-05

## Context
Hosts may register harness agents with a plugin/host prefix (`plugin-host:sdd-spec`), which
broke strict-equality recognition. At the same time, arbitrary `review-*` names must never be
accepted as harness-owned (closed-world invariant already enforced by `derivePhaseKey`).

## Decision
Resolution tolerates at most one prefix: a name containing `:` must contain exactly one colon
with non-empty sides; the remainder must itself match the closed set — pattern
`sdd-[a-z][a-z0-9-]*` (non-empty suffix) or the six-name review allowlist. Anything else
(including double-prefixed and foreign names) returns the sentinel `"unresolved"`, which makes
the emitter skip the record and the bench reject the row. No prefix allowlist: closed-set
membership of the remainder, not prefix matching, decides ownership.

## Alternatives
- Allowlist known prefixes (`ospec-workflow:`): prefixes are host-controlled and open-ended;
  gates the wrong thing.
- Strip all colon segments recursively: `a:b:sdd-spec` is malformed/foreign and must fail closed.
- Throw on foreign names: the SubagentStop hook must be fail-safe and never propagate errors.

## Consequences
Any single host prefix works without per-host knowledge; foreign agents cannot bypass coverage
via prefix strings. Unprefixed names resolve identically to today's values, so O1 attestations
stay valid without migration. Reversible by reverting the module and restoring strict equality.
